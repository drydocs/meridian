# Contract Error Reference

Every fallible entry point across Meridian's Soroban contracts returns a typed `ContractError` enum with a stable `u32` discriminant. When a simulation or transaction fails, Soroban surfaces the numeric code (for example `Error(Contract, #3)`).

Use this reference to map a contract error code to its root cause and the recommended client or operator response.

> **Note:** Error codes are scoped **per contract**. For example, code `3` is `DepositsPaused` on the vault, `NotInitialized` on both adapters, and `NonPositiveAmount` on the mUSDC token. Always identify which contract raised the error before looking up the code.

---

## Vault (`packages/contracts/vault/src/errors.rs`)

| Variant                          | Code | Cause                                                                                                                                                                            | Recommended Client / Operator Response                                                                                                                                                                            |
| -------------------------------- | ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AlreadyInitialized`             | 1    | `initialize` was called on a vault that already has an admin set (including any vault deployed via `__constructor`).                                                             | **Operator:** No action needed if the vault is already live. Do not re-run `initialize` on a deployed vault.                                                                                                      |
| `NotInitialized`                 | 2    | A state-mutating call was made before the vault was initialized.                                                                                                                 | **Operator:** Verify the configured vault contract ID and ensure deployment completed with valid constructor arguments.                                                                                           |
| `DepositsPaused`                 | 3    | `deposit` was called while `set_paused(true)` is active.                                                                                                                         | **Client:** Inform the user that deposits are temporarily paused and that withdrawals remain available. **Operator:** Check incident status before unpausing via `set_paused(false)`.                             |
| `ZeroAmount`                     | 4    | `deposit` or `withdraw` was called with a non-positive amount or share count (`<= 0`).                                                                                           | **Client:** Validate that the user-entered amount is strictly greater than zero before building the transaction.                                                                                                  |
| `DepositTooSmall`                | 5    | The deposited USDC amount rounds down to `0` shares at the current share price, or `migrate_adapter` received zero shares from the target adapter.                               | **Client:** Prompt the user to increase the deposit amount above the minimum dust threshold. **Operator:** If seen during `migrate_adapter`, inspect the target adapter's deposit return value.                   |
| `NoSharesOutstanding`            | 6    | `withdraw` was called while the vault has no mUSDC shares outstanding (`TOTAL_SH <= 0`).                                                                                         | **Client:** Refresh the user's position; there are no shares in the vault to redeem.                                                                                                                              |
| `InsufficientShares`             | 7    | The caller's live mUSDC balance is smaller than the requested withdrawal share count.                                                                                            | **Client:** Refresh the user's mUSDC balance and cap the withdrawal input to their available shares.                                                                                                              |
| `WithdrawalTooSmall`             | 8    | The burned share count rounds down to `0` USDC at the current share price.                                                                                                       | **Client:** Prompt the user to withdraw a larger share amount.                                                                                                                                                    |
| `Overflow`                       | 9    | An intermediate `i128` arithmetic operation overflowed.                                                                                                                          | **Client:** Reject abnormally large inputs and retry with a valid amount. **Operator:** Investigate adapter `total_assets()` or share supply values for anomalies.                                                |
| `AdapterSwapUnsafe`              | 10   | `set_adapter` was called while the vault still has shares outstanding (`TOTAL_SH > 0`) or the old adapter still holds a position (`ADPT_SH > 0`).                                | **Operator:** Do not use `set_adapter` on a live vault. Use the two-phase `begin_migration` + `migrate_adapter` flow instead.                                                                                     |
| `SameAdapter`                    | 11   | `begin_migration` or `migrate_adapter` was called with the vault's currently active adapter as the target.                                                                       | **Operator:** Verify the target adapter address; no migration is needed if it is already active.                                                                                                                  |
| `MigrationValueDrift`            | 12   | `migrate_adapter`'s post-migration value delta fell outside the `max_slippage_bps` tolerance of the pre-migration value.                                                         | **Operator:** Inspect liquidity, pool utilization, and slippage on both adapters. Retry when conditions stabilize or investigate the target adapter before raising `max_slippage_bps` (up to the 500 bps cap).    |
| `NoAdapterPosition`              | 13   | `migrate_adapter` was called while the active adapter has no recorded position (`ADPT_SH <= 0`).                                                                                 | **Operator:** If the vault is empty, use `set_adapter` instead. If `TOTAL_SH > 0` while `ADPT_SH <= 0`, escalate to incident response for counter desync.                                                         |
| `InvalidSlippageBps`             | 14   | `migrate_adapter` was called with `max_slippage_bps > 500` (`MAX_ADMIN_SLIPPAGE_BPS`).                                                                                           | **Operator:** Pass a `max_slippage_bps` value in the range `0..=500` (0% to 5%).                                                                                                                                  |
| `MinAmountOutNotMet`             | 15   | `withdraw` produced positive USDC, but net proceeds after performance fees fell below the caller's `min_usdc_out` floor.                                                         | **Client:** Re-simulate the withdrawal to fetch an updated quote, inform the user of the price/slippage change, and ask them to re-sign with an updated `min_usdc_out`.                                           |
| `NoPendingAdmin`                 | 16   | `accept_admin` was called when no `transfer_admin` nomination is pending.                                                                                                        | **Operator:** Confirm the current admin has called `transfer_admin(new_admin)` and that the nomination has not already been accepted.                                                                             |
| `AdapterReportedNoAssets`        | 17   | The active adapter reported `total_assets() <= 0` while the vault still has shares outstanding (`TOTAL_SH > 0`).                                                                 | **Client:** Show a temporary service error and do not retry blindly. **Operator:** Escalate immediately and inspect the active adapter and underlying protocol for insolvency, stale state, or a broken response. |
| `SlippageExceeded`               | 18   | `deposit` minted fewer shares than the caller's `min_shares_out` floor.                                                                                                          | **Client:** Re-simulate the deposit to refresh the share quote, surface the updated estimate to the user, and retry after confirmation.                                                                           |
| `MigrationNotInitialized`        | 19   | `migrate_adapter` or `get_migration_snapshot` was called without an active `begin_migration` snapshot for the target adapter.                                                    | **Operator:** Call `begin_migration(new_adapter)` first and wait for the cooldown before calling `migrate_adapter`.                                                                                               |
| `MigrationCooldownNotMet`        | 20   | `migrate_adapter` was called before `MIN_LEDGER_GAP` ledgers had elapsed since `begin_migration`.                                                                                | **Operator:** Wait until `current_ledger >= snapshot.ledger_seq + MIN_LEDGER_GAP` and retry. Keepers should reschedule for the target ledger.                                                                     |
| `MigrationStabilityDrift`        | 21   | The target adapter's pre-deposit `total_assets()` drifted below the `max_slippage_bps` floor relative to the `begin_migration` snapshot.                                         | **Operator:** Halt migration and investigate the target adapter/protocol for drainage or valuation manipulation during the cooldown window before re-running `begin_migration`.                                   |
| `MigrationSnapshotAssetsInvalid` | 22   | `begin_migration` was called against a target adapter reporting a negative `total_assets()`.                                                                                     | **Operator:** Do not migrate to this adapter; inspect the target adapter contract and underlying protocol state.                                                                                                  |
| `AdapterCreditedNothing`         | 23   | During `deposit`, the active adapter returned `<= 0` shares credited.                                                                                                            | **Client:** Inform the user the deposit could not be completed and no funds were minted. **Operator:** Inspect the underlying protocol (e.g. Blend pool caps or DeFindex vault status) and adapter logs.          |
| `DivisionByZero`                 | 24   | A `checked_div` encountered a zero divisor (degenerate adapter or share-pricing state).                                                                                          | **Client:** Show a temporary error and do not retry automatically. **Operator:** Inspect `total_assets()`, `TOTAL_SH`, and `ADPT_SH` for degenerate state.                                                        |
| `MigrationBaselineInvalid`       | 25   | `migrate_adapter` read `total_assets() <= 0` from the old adapter while the vault still holds adapter shares.                                                                    | **Operator:** Halt migration and run `accrue()` (for Blend) or investigate the old adapter/protocol before attempting recovery.                                                                                   |
| `ReentrancyDetected`             | 26   | A guarded entry point (`deposit`, `withdraw`, `rescue_token`, `begin_migration`, `migrate_adapter`, or `on_transfer`) was re-entered while another guarded call was in progress. | **Client:** Reject the transaction. **Operator:** Treat as a high-severity security alert; inspect the calling transaction and any custom adapter or token integrations.                                          |
| `AdapterUsdcMismatch`            | 27   | `set_adapter`, `begin_migration`, or constructor wiring was given a target whose `get_usdc()` differs from the vault's USDC, is missing, or fails.                               | **Operator:** Deploy the target adapter against this vault's USDC token, or redeploy it from the current source if it lacks `get_usdc()`, then retry.                                                             |
| `AdapterVaultMismatch`           | 28   | `set_adapter`, `begin_migration`, or constructor wiring was given a target whose `get_vault()` is not this vault, is missing, or fails.                                          | **Operator:** Deploy the target adapter bound to this vault, or redeploy it from the current source if it lacks `get_vault()`, then retry.                                                                        |
| `AdapterResidualPosition`        | 29   | `set_adapter` was given a target that already holds a position (nonzero `total_shares()` or `total_assets()`).                                                                   | **Operator:** Use a freshly deployed adapter with no shares or assets. Move any funds out of the target before wiring it in.                                                                                      |
| `DepositValueMismatch`           | 30   | `deposit`'s adapter reported a credit worth more than the USDC it was given or more than its `total_assets()` grew by, beyond the documented tolerance.                          | **Client:** Do not retry automatically; show a temporary error. **Operator:** Treat as an adapter accounting defect and compare the adapter's credited shares with its `total_assets()` change.                   |
| `MaxSharesExceeded`              | 31   | `withdraw_assets` burned share count exceeded the caller-specified maximum bound (`max_shares_in`).                                                                              | **Client:** Re-simulate to refresh the share price, then raise `max_shares_in` or request less USDC.                                                                                                              |
| `InvalidAdminAddress`            | 32   | Constructor initialization rejected a zero or vault-self admin address.                                                                                                          | **Operator:** Redeploy with a valid admin address that is not the vault itself.                                                                                                                                   |
| `InvalidUsdcAddress`             | 33   | Constructor initialization rejected a zero or vault-self USDC address.                                                                                                           | **Operator:** Redeploy with the USDC token contract address.                                                                                                                                                      |
| `InvalidMusdcAddress`            | 34   | Constructor initialization rejected a zero or vault-self mUSDC address.                                                                                                          | **Operator:** Redeploy with the mUSDC token contract address.                                                                                                                                                     |
| `InvalidAdapterAddress`          | 35   | Constructor initialization rejected a zero or vault-self adapter address.                                                                                                        | **Operator:** Redeploy with the adapter contract address.                                                                                                                                                         |
| `InvalidTreasuryAddress`         | 36   | Constructor initialization rejected a zero or vault-self treasury address.                                                                                                       | **Operator:** Redeploy with a treasury address that is not the vault itself.                                                                                                                                      |
| `MusdcAdminMismatch`             | 37   | Constructor initialization found that mUSDC is not administered by this vault.                                                                                                   | **Operator:** Deploy mUSDC with the vault as its admin before deploying the vault.                                                                                                                                |
| `ProtectedToken`                 | 38   | `rescue_token` was called for the vault's USDC, the mUSDC share token or the active adapter.                                                                                     | **Operator:** Rescue only unrelated tokens. USDC and mUSDC are never rescuable, and the active adapter must be changed through the migration flow.                                                                |
| `InsufficientBalance`            | 39   | `rescue_token` was asked for more of the token than the vault holds.                                                                                                             | **Operator:** Read the vault's balance of the token and retry with an amount no larger than it.                                                                                                                   |
| `DepositCapExceeded`             | 40   | `deposit` would take the vault's total assets above the cap set with `set_total_deposit_cap`.                                                                                    | **Client:** Show that deposits are at capacity and offer a smaller amount, or retry later. **Operator:** Raise the cap with `set_total_deposit_cap`, or set it to `0` to remove it.                               |
| `AdapterLiquidityInsufficient`   | 41   | The active adapter's available USDC liquidity is below the gross USDC needed for the requested withdrawal. Distinct from `WithdrawalTooSmall`.                                   | **Client:** Offer a smaller amount or retry later, since the underlying protocol is temporarily short of liquidity. **Operator:** Read `available_liquidity` to see how much can be withdrawn now.                |
| `NoPendingMigration`             | 42   | `cancel_migration` was called while no migration is pending.                                                                                                                     | **Operator:** Read `get_migration_snapshot` to confirm whether a migration is pending before cancelling.                                                                                                          |

## Blend Adapter (`packages/contracts/blend-adapter/src/errors.rs`)

> `adapter-common::AdapterError::AlreadyInitialized` (`1`) maps directly to `ContractError::AlreadyInitialized` (`1`).

| Variant              | Code | Cause                                                                                                                     | Recommended Client / Operator Response                                                                                                   |
| -------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `AlreadyInitialized` | 1    | `initialize` was called on a Blend adapter that already has a vault address set.                                          | **Operator:** No action needed if the adapter is already deployed and wired.                                                             |
| `Overflow`           | 2    | An intermediate `i128` arithmetic operation overflowed (for example during bToken/USDC conversion or balance accounting). | **Client:** Reject abnormally large amounts. **Operator:** Check the Blend pool reserve `b_rate` and adapter position size.              |
| `NotInitialized`     | 3    | A state-mutating or pool-reading call was made before the adapter was initialized.                                        | **Operator:** Verify the adapter contract address and ensure it was deployed with valid constructor arguments (`vault`, `pool`, `usdc`). |
| `DivisionByZero`     | 4    | A `checked_div` encountered a zero divisor, such as a zero `b_rate` returned by the Blend pool.                           | **Client:** Show a temporary protocol error. **Operator:** Inspect the Blend pool reserve state and verify the pool contract address.    |

## DeFindex Adapter (`packages/contracts/defindex-adapter/src/lib.rs`)

> `adapter-common::AdapterError::AlreadyInitialized` (`1`) maps directly to `ContractError::AlreadyInitialized` (`1`).

| Variant                     | Code | Cause                                                                                                                                                | Recommended Client / Operator Response                                                                                                                                                                                 |
| --------------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AlreadyInitialized`        | 1    | `initialize` was called on a DeFindex adapter that already has a vault address set.                                                                  | **Operator:** No action needed if the adapter is already deployed and wired.                                                                                                                                           |
| `Overflow`                  | 2    | An intermediate `i128` arithmetic operation overflowed (for example while computing the slippage floor or share/asset amounts).                      | **Client:** Reject abnormally large amounts. **Operator:** Inspect the DeFindex vault's share/asset valuation response.                                                                                                |
| `NotInitialized`            | 3    | A state-mutating or vault-reading call was made before the adapter was initialized.                                                                  | **Operator:** Verify the adapter contract address and ensure it was deployed with valid constructor arguments (`vault`, `dfx_vault`, `usdc`).                                                                          |
| `MalformedProtocolResponse` | 4    | The underlying DeFindex vault returned a response that cannot be interpreted as a valid asset valuation (e.g. an empty vector or missing index `0`). | **Client:** Show a temporary protocol error and do not retry blindly. **Operator:** Verify the configured DeFindex vault address and inspect its `get_asset_amounts_per_shares` / `deposit` / `withdraw` return shape. |

## mUSDC Token (`packages/contracts/musdc-token/src/lib.rs`)

| Variant                   | Code | Cause                                                                                                                             | Recommended Client / Operator Response                                                                                      |
| ------------------------- | ---- | --------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `AlreadyInitialized`      | 1    | `initialize` was called on an mUSDC token contract that already has an admin set.                                                 | **Operator:** No action needed if the token is already deployed.                                                            |
| `NotInitialized`          | 2    | A token entry point was called before `initialize` / `__constructor` configured the token.                                        | **Operator:** Verify the mUSDC contract address and deployment constructor arguments.                                       |
| `NonPositiveAmount`       | 3    | `transfer`, `transfer_from`, `burn`, `burn_from`, or `mint` was called with an amount `<= 0`.                                     | **Client:** Validate that the transfer or burn amount is strictly greater than zero before submitting.                      |
| `InsufficientBalance`     | 4    | The `from` address lacks sufficient mUSDC balance, or the `spender` lacks sufficient allowance for `transfer_from` / `burn_from`. | **Client:** Refresh the user's mUSDC balance and allowance; prompt them to reduce the amount or approve a higher allowance. |
| `InvalidExpirationLedger` | 5    | `approve` was called with an `expiration_ledger` that is in the past for a non-zero allowance (violating SEP-41).                 | **Client:** Fetch the latest ledger sequence from RPC and set `expiration_ledger` to a future ledger.                       |
| `Overflow`                | 6    | A balance or total-supply update would overflow `i128`.                                                                           | **Client:** Reject abnormally large amounts. **Operator:** Investigate token supply integrity.                              |
